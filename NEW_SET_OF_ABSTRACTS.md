# Preparing a new set of conference abstracts

This note describes how to add a conference year’s PDFs and abstracts to the
website. The 2026 paths and counts below reflect the materials currently
available; use the matching year and source files when repeating the process.

## 1. Check the source files

For 2026, the source folder is `/Users/bierlair/MyFiles/hEART/2026/`. It
contains `hEART2026_abstracts.csv`, `hEART2026_abstracts.md`, and 231 PDFs named
`paper_<paper_id>.pdf`.

Before staging anything, check that the source CSV has one row per paper, IDs
are unique, and each row’s PDF exists. The current set has 231 rows and PDFs.
Papers 79 and 190 are marked as using the abstract from the table as a
fallback; preserve those supplied abstracts even if the PDF extractor cannot
find a labelled abstract.

## 2. Stage the PDFs and make the website index

The site expects the year’s index CSV directly under `docs/abstracts/`, and
the corresponding PDF and generated HTML files in a year subdirectory:

```text
docs/abstracts/
├── papers_2026.csv
└── 2026/
    ├── paper_1.pdf
    ├── paper_1.html       # generated by build_site.py
    └── ...
```

Copy the PDFs into `docs/abstracts/2026/` (keeping the source copies until the
site has been checked). Create `docs/abstracts/papers_2026.csv` with the
columns `authors,title,pdf_file,abstract,table_abstract`, mapping each source
row to its PDF filename, for example `paper_1.pdf`. `build_site.py` uses the
first three fields; the metadata extractor also uses the two abstract fields
if PDF extraction does not find a labelled abstract. The PDF path is resolved
as `docs/abstracts/<year>/<pdf_file>`.

## 3. Prepare paper metadata

`extract_paper_metadata.py` first tries to extract an explicitly labelled
abstract from the PDF using `paper_metadata.py`; if that fails, it uses the
CSV's `abstract` field and then `table_abstract`. The latter preserves the
table fallbacks for papers 79 and 190. The extractor supports `--year` to
process only one year's CSV and `--merge` to update those records in the
existing `data/paper_metadata.json` without replacing other years. For 2026,
run:

```sh
python3 extract_paper_metadata.py --year 2026 --merge
```

The generated abstract text is displayed on each paper’s HTML page.

## 4. Update the conference availability flag

In `data/conferences.yml`, find the record with `year: 2026` and set
`abstracts_available: true` once the set is ready. This keeps the conference
record accurate. `update_database.py` loads this value into SQLite, and
`extract_conference.py` returns it with the conference data. The current
`build_site.py` paper listing is driven by `papers_2026.csv`; it does not use
this flag to decide whether to render the papers.

## 5. Rebuild the website

Run metadata preparation first, then rebuild the site from the repository
root using the project's Python environment. In this checkout, use
`./.venv/bin/python`; a system Python without the project dependencies may not
run the build. Use a temporary SQLite database path:

```sh
build_tmp="$(mktemp -d)"
./.venv/bin/python build_site.py "$build_tmp/heart.db"
```

`build_site.py` recreates the database file passed to it, so do not pass the
repository’s `heart.db` unless you intend to replace it. The build regenerates
the website pages and deletes generated `*.html` files under
`docs/abstracts/` before recreating the article pages from all yearly CSVs.
It preserves the PDFs and CSVs in that directory.

## 6. Verify before publishing

- Confirm the 2026 conference page lists all 231 papers and their authors.
- Open several generated HTML abstract pages, including papers 79 and 190,
  and check the displayed abstract and PDF download link.
- Check that all 231 PDF links resolve and that the generated 2026 pages are
  included in `docs/sitemap.xml`.
- Review `git status` and the diff for `data/paper_metadata.json`,
  `data/conferences.yml`, and generated `docs/` files. Keep unrelated changes
  out of the update.
